### 先划分，再建立词表

原始语料共 185 个字符，以 90% 为训练比例，向下取整后，前 166 个字符用于训练，后 19 个用于验证。

词表只根据训练文本建立，再加入 `<unk>`，共 95 项。验证段里的“层、早、果、沙、留、细”未出现在训练词表中，需要映射到未知字符 ID。

**先确定数据边界，再构建词表与样本。** 这样验证段的字符不会提前参与词表统计，取样也不会跨越训练与验证的分界。

### 看清切片与位移

下面是缩小后的独立手算示例。B = 2 表示一批两条样本，T = 3 表示每条样本包含三个预测位置。在交互实验中可以改变起始样本编号，对照两组数组如何一起移动。


一条样本需要连续的 T + 1 个 ID：前 T 项是输入，后 T 项是目标。样本起点每次前进 T，因此相邻样本共用一个边界 ID。

```text
k₀ = 0，B = 2，T = 3
第 0 条片段：[10, 11, 12, 13]
第 1 条片段：[13, 14, 15, 16]

xb = [                 yb = [
  [10, 11, 12],          [11, 12, 13],
  [13, 14, 15],          [14, 15, 16],
]                      ]
```

ID 13 是第一条样本的最后一个目标，也是第二条样本的第一个输入。每一行仍然有自己的上下文，组批并不会将两行接成更长的一段。

### 回到实际配置

原练习使用 B = 4、T = 8，输入和目标的形状都是 `[4, 8]`。训练段能取出 20 条完整样本。验证段只能取出两条完整样本，按当前批大小无法组成完整批。

本轮尚未实现短批处理或 padding。因此，样本不足时不能假装仍有四条数据，也不能借用另一分区的文本补齐。

源码见 [02_split_dataset.py](/source/batches/)，实现提交 `0ce7964`；最近自检记录见 [TASKS.md](/source/tasks/)。

### 检查自己的理解

<details><summary>为什么一条长度为 T 的输入，要取 T + 1 个 ID？</summary><div>输入的最后一个位置也需要一个“下一个 ID”作为目标。额外的一项正是这个目标；输入和目标本身的长度都仍然是 T。</div></details>

<details><summary>把样本堆成 batch，就完成了一次训练吗？</summary><div>没有。组批只是整理数据。训练还需要前向计算、损失、反向传播与参数更新；是否每批更新一次，还取决于梯度累积等设置。</div></details>
